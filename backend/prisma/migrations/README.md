# Migrations (`backend/prisma/migrations`)

The SQL that builds the database, applied in folder order by `prisma migrate deploy` (`bun run db:deploy`; `bun run db:setup` from the repo root). Each folder holds one `migration.sql`. Applied migrations are recorded in the `_prisma_migrations` table, so each runs once per database.

`migration_lock.toml` pins the provider to `postgresql`; Prisma manages it, do not edit it.

How to write a new migration, and the rules (never edit an applied migration, never reset a shared database), are in [../README.md](../README.md#migrations-workflow).

## Migrations

| Folder | What it does |
| --- | --- |
| `0_baseline` | The whole GradeBook schema at the point the app moved to its own Postgres, generated with `pg_dump` (row-level security removed). Creates the `extensions` schema with `pg_trgm`, the schemas `account`, `chat`, `course`, `file_manager`, `grading`, `public` and `student`, their 44 tables, enums, constraints and indexes, and the SQL functions the API calls: `public.redeem_school_join_code` (used by `src/student-account`), `public.student_duplicate_candidates` and `public.merge_student_records` (dropped by `20261027140000_drop_student_merge`), `public.join_school_by_email_domain`, `public.seed_school_system_roles`, `grading.submit_quiz` and `chat.unread_counts`. The 58 older migrations it replaces are in git history (see [../schema/README.md](../schema/README.md#changing-the-schema)). |
| `20261023120000_notifications_calendar` | Adds `course.course_notification`: one in-app notice per recipient about new work (`activity_published`) or a course `announcement`, unique per user and activity / announcement, with indexes for a user's list and unread count. The calendar itself needs no tables. |
| `20261023130000_grading_extras` | Adds `drop_lowest` / `drop_highest` to `course.assignment_group`; adds rubrics - `grading.rubric` (per course), `grading.rubric_criterion`, `grading.rubric_rating` and `grading.rubric_assessment` (the level chosen per submission and criterion, with its points); and `grading.activity.rubric_id` (set to null when the rubric is deleted). |
| `20261023140000_discussions` | Adds course discussions: `course.discussion_topic` (pinned, locked, published, require-initial-post), `course.discussion_reply` (threaded through `parent_id`, soft-deleted when it has replies), `course.discussion_read` (per-user read marker) and `course.discussion_setting` (per-course options such as `students_can_create_topics`). |
| `20261023150000_course_templates` | Adds `course.course.is_template` and a partial index on templates per school. |
| `20261023160000_module_discussions_notifications` | Adds the `discussion` value to `course.module_item_type`, `course.module_item.discussion_topic_id` (and updates the item-type check constraint, comparing as text because the new enum value cannot be used in the same transaction), and `course.course_notification.discussion_topic_id` with the new kinds `discussion_topic` and `discussion_reply` (one topic-published notice per user). |
| `20261024100000_billing` | (Dropped by `20261102100100_drop_billing`.) Creates the `billing` schema for the hosted platform: `subscription` (one per school), `invoice` (one live invoice of ours per school and period), `payment_event` (processed webhooks, unique per provider event for idempotency), `provider_setting` (per-provider on/off switch) and `platform_admin`. Only used when `BILLING_ENABLED=true`. |
| `20261025100000_drop_unenforced_permissions` | Deletes the permission keys nothing enforces from `public.permission_catalog`: `course:read`, `course:delete`, `student:delete` and `academic-year:delete` (reading and deleting a course are decided by the course role; students and academic years have no delete route). Role grants for them go too, because `school_role_permission` cascades on the catalog row. |
| `20261025120000_erasure_log` | Creates the `compliance` schema and `compliance.erasure_log`: one row per erasure of personal data (kind, subject table and uuids, school, actor uuid or `system`, reason, a `replay` plan of uuid-only steps, `exported_at` for the copy in object storage), with CHECK constraints on kind, reason and actor, no foreign keys (the log outlives its subjects), and indexes on `occurred_at`, `(school_id, occurred_at)` and unexported rows. See `src/erasure`. |
| `20261026100000_session_hardening` | Adds to `account.session`: `absolute_expires_at` (not null, default now + 90 days; existing rows get `created_at` + 90 days), `previous_token_hash` (unique), `rotated_at`, `revoked_reason` and `device`, plus a partial index on `(user_id, created_at desc)` for live sessions. Creates `account.known_device` (`user_id`, `fingerprint`, `first_seen_at`, `last_seen_at`; cascades with the user; index on `last_seen_at`) for new sign-in alerts. See `src/account`. |
| `20261027090000_session_grace` | Adds `account.session.rotation_confirmed_at`: when the token issued at the last rotation was first presented. While it is null, the replaced token can recover the session for up to a day from the same user agent instead of counting as a copied token. Existing rotated rows are backfilled as confirmed, so they keep the strict behaviour. See `src/account`. |
| `20261027100000_file_hardening` | Adds the partial index `idx_file_upload_leftovers` on `file_manager.file (created_at)` for `pending` and `failed` rows, which the retention job now purges after an hour. See `src/retention`. |
| `20261027110000_billing_hardening` | (Dropped by `20261102100100_drop_billing`.) Adds `billing.subscription.pending_checkout_id` (the last hosted checkout, expired before a new one starts) and `last_event_at` (newest provider event applied; older ones are ignored), `billing.payment_event.processing_at` (an atomic claim so concurrent deliveries apply once; taken over after 5 minutes) and `billing.job_lease` (a time-limited lease per background job, replacing the scheduler's advisory-lock transaction). See `src/billing`. |
| `20261027120000_grading_hardening` | Redefines `grading.submit_quiz` to refuse a retake (`already_marked`, `P0025`) once a teacher has marked the submission by hand or by import (`graded_by` set). Otherwise identical to `0_baseline`. |
| `20261027130000_sign_in_codes` | Adds `account.email_code.ip_hash` (keyed hash of the client that asked for the code, for the per-client send cap) and `account.email_code_attempt` (wrong guesses per code and client, primary key `(code_id, ip_hash)`, cascades with the code), so one client running out of guesses does not lock the owner out; `email_code.attempts` stays the total. See `src/account`. |
| `20261027140000_drop_student_merge` | Drops `public.student_duplicate_candidates` and `public.merge_student_records`. Students are only created by joining themselves (join code or student email domain), never by staff, so there are no duplicates to find or merge. The `merge` erasure-log reason stays allowed so older entries still replay. See `src/student-account`. |
| `20261027150000_join_code_permissions` | Replaces the unenforced `student:create` permission with dedicated `join-code:read` (view join code status) and `join-code:update` (issue and revoke join code). Migrates existing custom role grants and deletes `student:create` from `public.permission_catalog`. See `src/permission`. |
| `20261030100000_school_upload_limit` | Adds `public.school.max_upload_mb` (nullable integer, CHECK between 1 and 1000): the school's own upload limit in MB. Null follows `UPLOAD_DEFAULT_MB`; the API also caps it at `UPLOAD_MAX_MB`. See `src/file-manager`. |
| `20261101100000_course_appearance` | Adds `course.course.banner_color` (nullable text, CHECK one of `indigo`, `violet`, `blue`, `sky`, `teal`, `green`, `amber`, `orange`, `rose`, `slate`; null is the id-derived gradient) and `banner_image_path` (nullable storage key of the cover image under `images/course-banners/`). See `src/course`. |
| `20261101110000_school_logo` | Adds `public.school.logo_path` (nullable storage key of the school's logo under `images/school-logos/`). See `src/school`. |
| `20261102100000_organisation` | Adds `public.organisation` (`id`, `name` with a CHECK of 1-120 characters after trimming, `created_at`, `updated_at`), kept to one row by the unique index `organisation_singleton` on the constant `(true)`, and `public.organisation_admin` (`user_id` primary key referencing `user_profile`, cascading; `created_at`; `created_by` referencing `user_profile`, set null on delete). Copies every `billing.platform_admin` user who has a profile into `organisation_admin`, so the hosted platform's operators keep running the install. See `src/organisation`. |
| `20261102100100_drop_billing` | Drops the `billing` schema and its data (`subscription`, `invoice`, `payment_event`, `provider_setting`, `job_lease`, `platform_admin`): GradeBook is self-hosted, not a paid service. Runs after `20261102100000_organisation`, which copied the platform admins. `account.session.revoked_reason` has no CHECK, so old `platform_admin` revocations stay as they are; new ones read `organisation_admin`. |
| `20261102120000_features` | Adds `public.organisation.features` (`jsonb`, not null, default `{}`, CHECK it is a JSON object): the organisation's platform feature overrides (`key → boolean`) over the defaults in `src/features/feature.catalog.ts`; unknown keys are ignored. Adds `public.school.disabled_features` (`text[]`, not null, default `{}`): the features the school's admin switched off (a school can never switch on what the organisation does not allow). Replaces the `CHAT_CHANNELS_ENABLED` env var (now the `chat_channels` feature). See `src/features`. |
| `20261102130000_school_types` | Adds `preschool`, `middle`, `all_through`, `sixth_form`, `college`, `university`, `vocational`, `special_education`, `online` and `other` to the `public.schooltype` enum (alongside `primary` and `secondary`). |
| `20261103100000_sso_settings` | Adds `public.sso_provider_setting` (`provider` text primary key = adapter id such as `google`, `azure`, `saml`; `enabled` boolean; `client_id`; `client_secret_enc` - AES-256-GCM ciphertext under a key derived from `AUTH_SECRET`, never plaintext; `extra` jsonb object of non-secret settings, CHECK it is an object; `updated_at`; `updated_by` uuid without a foreign key). Sign-in providers configured from the organisation console; with no row a provider follows the env vars as before. Rotating `AUTH_SECRET` means re-entering the secrets. See `src/sso`. |
| `20261103110000_invites` | Adds `public.organisation_invite`: an invite for an email with no account yet to be a school's admin (`kind` `school_admin`, `school_id` required, cascading with the school) or an organisation admin (`organisation_admin`, `school_id` null). `email` is lower-cased (CHECK), `invited_by` / `accepted_by` reference `user_profile` (set null), `expires_at` defaults to now + 14 days, `accepted_at` / `revoked_at` null while open. Partial unique indexes allow one open `school_admin` invite per school and one open `organisation_admin` invite per email; a partial index finds a signing-in email's open invites. See `src/organisation`. |

The models for these tables are in [`../schema/`](../schema/README.md).

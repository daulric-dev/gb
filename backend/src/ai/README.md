# AI assistance (`src/ai`)

Teacher-initiated, teacher-approved AI drafts through the **organisation's own AI provider** (bring your own: Anthropic, or any OpenAI-compatible service). Behind the feature `ai_assistance` (off by default; the organisation turns it on, a school can switch it off). ROADMAP item 17. Admin and teacher guide: [docs/content/guide/ai-assistance.md](../../../docs/content/guide/ai-assistance.md).

**Owner decisions:** each organisation brings its own provider(s) and sets the models on the platform for its schools to use; schools choose among the providers the organisation makes available but never add providers, keys or models. The AI never grades and never writes anything students can see: every route returns drafts, and a teacher accepts a draft through the normal routes (adding a question, saving a rubric mark, saving the page). It never sees data from a school with the flag off, and every request is logged.

## HTTP routes

### Organisation console (`OrganisationAiController`)

`AuthGuard` + `OrganisationAdminGuard` + `AiOrgFeatureGuard` (`FeatureService.assertEnabled(null, 'ai_assistance')`: the organisation's own setting; 403 `FEATURE_DISABLED` while off). Writes need step-up (`@RequireStepUp`) and are audited.

| Method | Path | Step-up | What it does |
| --- | --- | --- | --- |
| GET | `/api/organisation/ai/providers` | | `{ providers[], suggestions }`. Each provider: `id, name, kind, baseUrl, host, model, hasKey, keyLast4, keyUnreadable, monthlyCap, isDefault, allowPrivateNetwork, availableToSchools, usedThisMonth`. Never the key. |
| POST | `/api/organisation/ai/providers` | yes | `{ name, kind: 'anthropic' \| 'openai_compatible', baseUrl?, model?, apiKey, monthlyCap?, isDefault?, allowPrivateNetwork? (default false), availableToSchools? (default true) }`. `baseUrl` is optional for Anthropic (an override, e.g. a gateway) and required for OpenAI-compatible. `model` defaults to `claude-opus-5-5` for Anthropic. The first provider becomes the default. |
| PATCH | `/api/organisation/ai/providers/:id` | yes | Name, base URL, model, `monthlyCap` (`null` removes it), `allowPrivateNetwork`, `availableToSchools`; a non-empty `apiKey` replaces the key. The kind cannot change. Turning `allowPrivateNetwork` off while the base URL is `http` is a 400. |
| POST | `/api/organisation/ai/providers/:id/default` | yes | Make it the default. |
| DELETE | `/api/organisation/ai/providers/:id` | yes | 204. The log keeps the copied name; the oldest other provider becomes the default; schools that chose it go back to the organisation default (FK `ON DELETE SET NULL`). |
| POST | `/api/organisation/ai/providers/:id/test` | | Test the **saved** provider (a tiny structured request). `{ ok, message }`. Throttled to 10 a minute. |
| GET / PUT | `/api/organisation/ai/settings` | PUT | `{ keepPrompts, userHourlyLimit (1-1000, default 30) }`. Turning `keepPrompts` off clears what was kept. |
| GET | `/api/organisation/ai/usage` | | The newest 100 requests (no content) and this month's total. |

### School (`SchoolAiController`, `PermissionGuard` + `school:update`, the active school)

| Method | Path | What it does |
| --- | --- | --- |
| GET / PUT | `/api/schools/current/ai` | PUT `{ allowStudentWork?, providerId? }` (`allowStudentWork` default false; `providerId` a provider with `available_to_schools`, `null` = organisation default, left out = unchanged; anything else is a 400). ### Course builder (`CourseBuilderAiController`, `AuthGuard`; `AiCourseService` checks the course role and `ai_assistance` for the course's school)

Teacher material only: what the teacher typed or pasted, the course's name, code and description, and titles in the course. **No student data is read or sent** (emails and phone-like numbers in teacher text are still replaced). Every `ai/...` route returns drafts only; `ai/plan/create` is the one route that creates anything. Manage = course teachers and admins (**not TAs**).

| Method | Path | Role | What it does |
| --- | --- | --- | --- |
| POST | `/api/courses/:courseId/ai/outline` | manage | `{ subject, level, weeks? (1-52) \| units? (1-20), goals?, syllabus? (≤ 30 000 chars), assessments? (0-100), mix? (balanced, more_quizzes, more_assignments, quizzes_only, assignments_only), outcomes?, groups? (default true) }` → `{ plan: { modules[] }, masteryOn, startDate (term, else academic year, start; or null), existingGroups[], requestId, provider, note }`. Outcomes are asked for only while `mastery` is on. |
| POST | `/api/courses/:courseId/ai/plan/create` | manage | The reviewed plan: `{ modules[{ title, overview?, existingModuleId?, items[], outcomes? }] (1-20), startDate? (YYYY-MM-DD), createOutcomes? (default true), overviewPages? (default false), draftQuestions? }` → a report (below). Not an AI request (nothing is sent; not counted). Throttled to 5 a minute; one plan at a time per course (409). |
| POST | `/api/courses/:courseId/modules/:moduleId/ai/items` | manage | `{ brief?, count? (1-15), level? }` → `{ moduleId, moduleTitle, items[] }` (plan item shape, no due weeks or outcomes). "Add selected" sends them to `ai/plan/create` with `existingModuleId`. |
| POST | `/api/courses/:courseId/ai/page-content` | manage | `{ title, outline?, level? }` → `{ markdown }` (safe Markdown, ≤ 20 000 chars). |
| POST | `/api/courses/:courseId/ai/assignment-instructions` | manage | `{ title, brief?, level?, points? }` → `{ instructions, points, submission: text \| file \| text_and_file, allowText, allowFile }`. |
| POST | `/api/courses/:courseId/ai/rubric` | manage | `{ title, instructions?, totalPoints?, criteria? (1-10), level? }` → `{ rubric: { title, criteria[{ title, description, points, ratings[{ label, description, points }] }] }, dropped }`, in the shape `POST /courses/:id/rubrics` takes. Each criterion is checked with `validateRubricCriteria` (src/grading/rubric.service.ts); one that breaks it is dropped (counted); none left ⇒ 502 `AI_INVALID_OUTPUT`. Saved only through the rubric routes. |
| POST | `/api/courses/:courseId/ai/announcement` | staff (TAs too, as for posting course announcements) | `{ prompt }` → `{ title, body }` (limits of `CreateAnnouncementDto`). Written for the course's students. |
| POST | `/api/courses/:courseId/ai/outcomes` | manage, `mastery` on (403 otherwise) | `{ brief?, count? (1-20), level? }` → `{ outcomes[{ code, title, description }] }` from the course's module, page and activity titles; codes already in the course are dropped. Added through the normal outcome route. |

**Plan item** (outline and module suggestions; `PLAN_ITEM_SCHEMA`): `{ kind: page | assignment | quiz, title (1-200), description (page: outline; assignment: instructions; quiz: topic), points (number 0-1000 \| null), dueOffsetWeeks (integer 0-104 \| null), questionCount (integer 1-10 \| null), group (assignment group name or ""), submission ("" \| text \| file \| text_and_file), outcomes (codes of the module's outcomes) }`. Module: `{ title, overview, items (≤ 15), outcomes[{ code, title }] (≤ 8) }`; outline ≤ 20 modules (`AI_PLAN_MAX_*`). `cleanOutline` / `cleanPlanItem` (`course-plan.ts`) make it consistent: titles plain text, descriptions `safeMarkdown`, fields that do not apply to the kind cleared (a page has no points, group, due week or outcomes), defaults (assignment 10 points and text submission; quiz 5 questions and one point each), outcome codes unique across the plan and item references limited to the module's codes. The teacher's plan is cleaned again on create.

**Creating a plan** (`AiCourseService.createFromPlan`): through the existing services only (each write in its own audited transaction, with its own permission check; nothing writes tables directly): `AssignmentGroupService.list/create` (groups matched case-insensitively, else created), `OutcomeService.createCourseOutcome` / `align` (only while `mastery` is on and `createOutcomes` is not false; an outcome whose code exists is reused), `ModuleService.create` (unpublished) / `createItem`, `PageService.create` (`isPublished: false`, body = the outline), `ActivityService.create` (status `draft`; assignment `allowText` / `allowFile` from the submission type; quiz instructions = its topic; points = plan points). **Quizzes are created empty:** questions have no pending-draft state, so none is ever added; with `draftQuestions` the report lists the quizzes and the quiz builder opens **Draft questions with AI** (`?aiDraft=1`) with the topic as the pasted text. **Due dates:** `dueDateFor(start, weeks)` = start + 7 × weeks days at 23:59 UTC; start = `startDate`, else the course's term `start_date`, else its academic year's; none ⇒ no due dates (and a note). **Partial failures:** the services cannot share one transaction, so creation continues past a failure and reports it: `{ ok, created{ modules, items, groups, outcomes }, failed, startDate, modules[{ title, moduleId, status: created|existing|failed, error, items[{ kind, title, status: created|failed|not_added|skipped, id, error, dueAt, aligned[] }] }], groups[], outcomes[], quizzes[{ activityId, title, topic, questionCount }], draftQuestions, notes[] }` (`not_added`: created but not added to the module; `skipped`: its module failed).

Generating routes are throttled to 10 a minute per session on top of the hourly limit. Errors: 409 `AI_NO_PROVIDER` / `AI_KEY_UNREADABLE`, 429 `AI_RATE_LIMITED` / `AI_CAP_REACHED`, 422 `AI_REFUSED` (with `category` when the provider gives one) / `AI_TRUNCATED`, 502 `AI_INVALID_OUTPUT` / `AI_PROVIDER_ERROR`.

## Design

- **`AiGateway.generateStructured(config, { system, user, schema, name })`** is the provider-neutral interface every feature uses. It picks the adapter for the provider's kind, parses the answer (`parseJsonText`) and validates it against the same schema (`json-schema.ts`, `validateSchema`) before anything reads it; a mismatch is `invalid_output`. `providerSchema()` strips the constraints structured outputs reject (lengths, ranges, counts); they are enforced locally.
- **`AnthropicAdapter`** (`adapters/anthropic.adapter.ts`): the official `@anthropic-ai/sdk` (pinned `1.4.0`). `new Anthropic({ apiKey, baseURL: config.baseUrl ?? 'https://api.anthropic.com', fetch: guardedFetch(), timeout, maxRetries: 1 })` (an explicit key, so `ANTHROPIC_*` environment credentials are never used), then `client.beta.messages.create({ model, max_tokens: 16000, system, messages, output_config: { effort: 'medium', format: { type: 'json_schema', schema } }, betas: ['server-side-fallback-2026-07-01'], fallbacks: 'default' })`. Non-streaming. The fallbacks beta (server-side refusal fallback) is sent for `claude-opus-5-5` and the other models that take it; `effort` only for models that accept it. No `thinking` parameter: adaptive thinking is the default and disabling it or a budget is a 400 on `claude-opus-5-5`. No forced `tool_choice` (also a 400 there): structured outputs instead. `client.messages.parse()` is not used (it needs zod, not a dependency, and the beta endpoint is needed for fallbacks); validation is ours. `stop_reason` is always checked: `refusal` → `refused` (with `stop_details.category`), `max_tokens` / `model_context_window_exceeded` → `truncated`. Errors are mapped by SDK class (`Anthropic.AuthenticationError`, `RateLimitError`, `NotFoundError`, `BadRequestError`, `APIConnectionTimeoutError`, `APIConnectionError`, `APIError`), never by message text.
- **`OpenAiCompatibleAdapter`**: `POST {baseUrl}/chat/completions` with `Authorization: Bearer <key>` and `response_format: { type: 'json_schema', json_schema: { name, strict: true, schema } }`; a 400/422 is retried once without `response_format`, with the schema in the system prompt and "JSON only". `finish_reason: 'length'` → `truncated`; `content_filter` or `message.refusal` → `refused`.
- **Output budget:** `RunRequest.maxTokens` per feature (`AI_FEATURE_MAX_TOKENS`): the outline gets the full `AI_MAX_OUTPUT_TOKENS` (16 000), page content 12 000, module items 8 000, instructions / rubric / outcomes 6 000, announcements 4 000. The Anthropic adapter sends it as `max_tokens` (never above 16 000, non-streaming); OpenAI-compatible requests send no limit (parameter names differ between servers). The timeout is the same `AI_REQUEST_TIMEOUT_MS`. Each generation is one `ai_request` row, so it counts once toward the hourly limit and monthly cap.
- **System prompts** (`prompts.ts`) are constants with no ids, names or timestamps (cacheable). The request material goes in the user message inside tags (`<material>`, `<student_work>`, `<page>`) and the prompts tell the model to treat it as content, not instructions. Rubric criteria and levels are sent as short references (`c1`, `c1-r2`), never ids, and mapped back; a level of another criterion is dropped.
- **Output is untrusted:** only validated fields are read; text goes through `plainText()` (HTML tags removed, Markdown images and links reduced to their text) so an inserted summary can never load or link to something the model chose; course-building Markdown (pages, instructions, announcements, outlines) goes through `safeMarkdown()` (`redact.ts`: no HTML, images, links or bare URLs unless the teacher supplied that exact URL, `suppliedUrls()`); question drafts go through `validateQuestion` and rubric drafts through `validateRubricCriteria`. Nothing is executed or rendered as HTML.
- **`AiService.run`**: logs a `pending` `ai_request` row first, refuses past the user's hourly limit (`ai_org_setting.user_hourly_limit`, rolling hour) or the provider's `monthly_cap` (calendar month, UTC) with 429 (the row becomes `rate_limited` / `cap_reached`, nothing is sent), decrypts the key, calls the gateway, and finishes the row (`ok`, `refused`, `truncated`, `invalid_output`, `error`; model, tokens, duration). An audit entry `ai_request` (feature, course, provider, model, status; never content) goes to the school's audit log. A sweep (every 6 h per instance) clears kept prompts after 30 days and deletes log rows after a year.
- **Provider selection** (`resolveSchoolProvider`, `AiService.requireProvider(schoolId)`): the school's choice (`ai_school_setting.provider_id`) while it still exists and is `available_to_schools`; else the organisation default (`selectProvider`: the default, else the only one) if it is `available_to_schools`; otherwise 409 `AI_NO_PROVIDER`. Organisation-level connection tests use the tested provider directly.

## Privacy

- Only what the feature needs is sent: the chosen page or pasted text (quiz questions, summaries), or the rubric, the activity's title and instructions and the student's handed-in **text** (rubric feedback; files are never sent). Course building sends teacher material only (see above): no student table is read.
- **Redaction** (`redact.ts`) before sending: email addresses → `[email]`, phone-like numbers → `[number]`, the student's names (full, first, last) → `[Student]`, classmates' names (every student of the course) → `[Classmate]`. Case-insensitive, whole words, longest first. In rubric suggestions shown to the teacher, `[Student]` is turned back into the student's first name.
- Student work is sent only for rubric feedback and only when the school's `allow_student_work` is on (default off), checked before the submission is read.
- Prompts and answers are **not stored** unless the organisation turns on `keep_prompts` (30 days, then cleared; turning it off clears them at once).
- `dataNotice()` is the plain-language notice naming the provider and its host, shown on the school settings card and the teacher dialogs.

## Security

- API keys: AES-256-GCM via `src/account/secret-box.ts` (info `gradebook:ai-provider-key:v1`, AAD `ai-provider:<id>`; DATA_ENCRYPTION_KEY when set, else AUTH_SECRET). Never returned, logged or audited (`api_key_set` / `api_key_changed: true` only); the UI shows the last four characters.
- **Every outbound call** goes through `guardedFetch(transport, maxBytes, { allowPrivate })` (`ai-fetch.ts`), built per request by `AiGateway` from the provider's `allow_private_network`. It wraps the webhook sender's `safeWebhookFetch` (DNS resolved per request, the checked IP pinned, redirects never followed) and always passes an **explicit** `allowPrivate` down to `resolveWebhookDestination`, so `WEBHOOK_ALLOW_PRIVATE` never applies to AI: private / loopback / reserved addresses are refused unless the organisation marked that provider as running on its private network. It adds: https only (http only for a private-network provider), no credentials, query or fragment in the base URL, a 4 MB response cap. The Anthropic SDK receives it as its `fetch`, so the SDK's requests (and retries) get the same guard. Timeout `AI_REQUEST_TIMEOUT_MS` (default 120 s).
- Base URLs are validated on save (behind step-up) and only **saved** providers are tested: no request body reaches an outbound request (CodeQL `js/request-forgery`).
- A local model server (Ollama, vLLM, LM Studio) on a private address: the organisation admin ticks "This provider runs on our private network" on that provider (step-up, audited as `allow_private_network`). Only that provider may then reach private addresses or use http. `WEBHOOK_ALLOW_PRIVATE` is not needed and has no effect on AI (it still governs webhooks, LTI keysets and OneRoster).
